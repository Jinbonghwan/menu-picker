# UX 설계 — 오늘 뭐 먹지?

## 1. 사용자 플로우

```
[진입]
  ↓
카테고리 선택 (기본값: 전체)
  ↓
"오늘의 메뉴 뽑기" 클릭
  ↓
[뽑는 중] 슬롯머신 애니메이션 (약 1.4초)
  ↓
[결과] 최종 메뉴 표시 + 하단 안내 문구
  ↓
(다시 뽑기 / 카테고리 변경 후 재시도)
```

전체 여정이 **단일 화면(1 스크린)** 안에서 끝난다. 페이지 이동이나 로딩 대기가
없어서 "오늘 뭐 먹지"라는 순간적인 고민에 바로 대응할 수 있다.

## 2. 화면 상태 (State) 정의
| 상태 | 트리거 | 화면 변화 |
|---|---|---|
| idle | 최초 진입 / 카테고리 변경 | 결과창에 `?` 표시, 버튼 활성화 |
| spinning | 뽑기 버튼 클릭 | 결과창에 메뉴 이름이 빠르게 바뀜, 버튼 비활성화 + "뽑는 중..." 텍스트 |
| result | 애니메이션 종료 | 최종 메뉴 확정 표시, 하단에 "오늘의 메뉴는 OO 입니다!" 문구 노출 |

## 3. 인터랙션 원칙
- **한 화면, 한 가지 주요 행동**: 카테고리 선택은 보조 행동, 뽑기 버튼이 주행동(Primary CTA).
- **되돌릴 수 있는 선택**: 카테고리는 언제든 바꿀 수 있고, 다시 뽑기도 제한 없이 가능.
- **로딩 상태의 명확한 피드백**: 뽑는 동안 버튼을 비활성화하고 문구를 바꿔 "지금 진행 중"임을 알림 (중복 클릭 방지).
- **즉각적인 만족감**: 애니메이션 시간을 1.4초로 제한해 지루하지 않게, 하지만 "뽑는 느낌"은 느껴지도록 함.

## 4. 엣지 케이스
- 카테고리를 뽑는 도중에 변경하면? → `spinning` 중에는 카테고리 변경 버튼도 비활성화 처리하여 애니메이션 중 상태 꼬임 방지.
- 카테고리에 메뉴가 없는 경우 → 현재는 모든 카테고리에 메뉴가 채워져 있어 발생하지 않지만, 추후 사용자 정의 카테고리 추가 시 빈 배열 방어 로직 필요 (`pool.length === 0`이면 뽑기 무시).

## 5. 접근성 고려
- 버튼에 `disabled` 상태를 명확히 부여해 스크린 리더 사용자도 진행 상태를 인지 가능.
- 텍스트 대비(짙은 회색/검정 vs 흰 배경)로 저시력 사용자도 읽기 쉽게 구성.
